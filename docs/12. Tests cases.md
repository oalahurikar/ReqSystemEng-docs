
> You don't need code to define a test. You need a structured Protocol. In your ICD (Ontology), a TestCase node should contain these four fields:

### How Test data will look like => Excel, Digital Twin, Mock data

| Field                       | Definition                                                       | Example                                                                                  |
|-----------------------------|------------------------------------------------------------------|------------------------------------------------------------------------------------------|
| 1. Pre-Conditions (Setup)   | What must be true before the test starts? This usually points to your Scenario. | Scenario: High Wind. Wind Tunnel set to 15m/s. Battery at 50% charge.                    |
| 2. Stimulus (Action)        | What do you do to the system?                                    | Command the Flight Controller to 'Hold Position' for 60 seconds.                         |
| 3. Expected Result          | What should happen (according to the Requirement)?               | Drone position must not drift more than 1.0 meter from the center.                       |
| 4. Pass/Fail Criteria       | The strict math used to grade the exam.                          | IF (Drift_Distance <= 1.0m) THEN PASS ELSE FAIL                                          |

## How to Write Tests (The Levels of Abstraction)

Writing tests depends entirely on which "Layer" (L1-L4) you are testing. The logic changes from "Business Value" to "Code Logic."

### Level 1: Acceptance Tests (Validation)

- **Target:** L1 Requirements / JTBD
- **Key Question:** Did the user get value?
- **How to write:** Focus on the Outcome, not the physics.
- **Example:**
  - **Requirement:** "Deliver payload to rural clinic."
  - **Test Case:** "Pack 2kg blood. Fly autonomous route. Verify package arrives at destination coordinates."

---

### Level 2: System Tests (Physics Verification)

- **Target:** L2 System Requirements
- **Key Question:** Does the machine obey the laws of physics defined in the Scenarios?
- **How to write:** Focus on the Constraints across the whole system.
- **Example:**
  - **Requirement:** "System shall maintain position in 15m/s wind."
  - **Test Case:** "Place drone in Wind Tunnel. Set wind = 15m/s. Log GPS coordinates. Calculate max deviation."

---

### Level 3: Integration Tests (The Handshake)

- **Target:** L3 Component Requirements & ICDs
- **Key Question:** Do the components talk to each other correctly?
- **How to write:** Focus on the Interface (Inputs/Outputs).
- **Example:**
  - **Requirement:** "Flight Computer shall send Motor Speed command via UART."
  - **Test Case:** "Connect Logic Analyzer to UART pin. Send 'Throttle 50%' command. Verify hex packet 0x32 is transmitted."

---

### Level 4: Unit Tests (The Code Logic)

- **Target:** L4 Implementation Requirements
- **Key Question:** Does this specific function or circuit work?
- **How to write:** Focus on Inputs vs. Returns.
- **Example:**
  - **Requirement:** "PID Loop shall clamp output to max 100."
  - **Test Case:** "Inject Error = 9999 into the PID function. Verify function returns exactly 100."

---

## How to "Bake" This Into Your Tool

Since you are building a tool, you need to guide the user to write these correctly.

**The "Test Case Wizard" Feature:**
- When a user clicks **"Add Test Case"** to a Requirement, your tool should auto-fill the fields based on the Requirement text.

#### Example Flow

1. **User Selects Requirement:**
   > REQ-100: "Max Drift < 1.0m in High Wind"
2. **Tool Checks ICD**:
   - **Extracts Scenario:** "High Wind" &rarr; Auto-fills *Pre-Condition*
   - **Extracts Constraint:** "Drift < 1.0m" &rarr; Auto-fills *Pass/Fail Criteria*
3. **User Writes Steps:**  
   User only needs to type how to measure it (e.g., "Use Vicon motion capture system").

---

## Summary

To write a test case without code, simply ask:

- **Setup:** What world am I in? (*Scenario*)
- **Action:** What do I poke? (*Stimulus*)
- **Success:** What does "Good" look like? (*The Requirement Limit*)

If you can write those three sentences, you have written a formal Test Case.
